# Test Plan: External Services & Required Credentials

The site has **3 active forms** plus off-site links. Here's what you need to test full functionality.

## External Services & Credentials Required

| # | Service | Config File | What's Needed | Used By |
|---|---|---|---|---|
| 1 | **Brevo API** | `user/config/plugins/brevo.yaml` | Real v3 API key (replace `YOUR_BREVO_V3_API_KEY`) | Newsletter signup (list 1) + Membership form (list 2) |
| 2 | **SMTP / Email** | `user/config/plugins/email.yaml` | Working `sendmail` MTA in container OR SMTP credentials (server/user/password); also set `from` address | Membership form + Auslagenerstattung form (with PDF attachment) |
| 3 | **Grav API** (for MCP only) | `opencode.json` | Generated via `bin/plugin api keys:generate` | Admin/automation — not user-facing |

No other external services need credentials. Form spam protection is self-hosted (`cap` proof-of-work + honeypot) and needs no credentials. GoCardless, eveeno, NextCloud, Google Translate, and Font Awesome CDN are off-site links/embeds with no integration to configure.

## Test Keys (for quick testing without real accounts)

For **hCaptcha**, the official test keys work without registration:

- Site Key: `10000000-ffff-ffff-ffff-000000000001`
- Secret Key: `0x0000000000000000000000000000000000000000`

For **Brevo**, you need a real Brevo account — a free tier works. Without it, the form appears to succeed to the user but logs an error silently and adds no contact.

For **Email**, easiest is to point SMTP at a transactional provider (Brevo SMTP, Mailtrap for testing, or Gmail SMTP). Mailtrap is ideal for testing — it captures all outbound mail without delivering it, so you can verify the PDF attachment and form contents.

## Functional Test Checklist

1. **Newsletter form** (home page) → verify contact lands in Brevo list 1 ✅ **TESTED — Brevo integration works**
2. **Membership form** (`/der-verein/vereinsmitglied-werden/kommunikation`) → Brevo list 2 ✅ **Brevo TESTED — works** + email to `vorstand@dckn.de` + hCaptcha validation ✅ **hCaptcha TESTED with test key — works**
3. **Auslagenerstattung form** (`/faq/auslagenerstattung`) → file upload (PDF/PNG/JPEG/TIFF, ≤1 MB), signature pad, hCaptcha, email with `auslagenerstattung.pdf` attachment generated by the custom `signature-attachment` plugin via Dompdf
4. **GoCardless flow** → verify the 5 payment links redirect off-site and users can find the hidden membership form afterward
5. **Projektförderung page** (`/der-verein/projektfoerderung-beantragen`) → full Projektantrag form: text fields, date, numbers, checkboxes (Vereinszwecke), 1000-char textareas, ODS-only upload, acceptance checkbox, signature pad; email to `vorstand@dckn.de` with the ODS attached + `projektantrag.pdf` generated by `signature-attachment` (form-aware since 2026-09-26)

## Two Things Worth Knowing Before You Test

1. The `signature-attachment` plugin fires on **every** email, not just Auslagenerstattung — so the membership email also gets a PDF. May be unintended.
   ↳ *Resolved 2026-09-26*: the plugin now skips forms without a `signature` field and picks a form-specific template (`pdf-template-<form-name>.html.twig`), so the membership email no longer gets a PDF and the Projektantrag gets its own `projektantrag.pdf`.
2. Forms with cap: first submission waits for the proof-of-work token; without JS the submission is rejected by design.
